# HD2 黑名单 · 绝地潜兵2 TK 者黑名单提示工具

**当前版本：v2.0.0** · Windows 10 / 11（64 位）· [MIT 许可](LICENSE)

一个 **纯本地** 的 Windows 桌面小工具：读取游戏内插件写出的队友名单日志，
在你遇到记录在案的 TK 玩家 **刚进队** 时，用 **不抢焦点** 的音效 + 半透明 Overlay
小窗提醒你。

> **不注入进程 · 不读游戏内存 · 不改游戏包 · 不抢焦点 · 不打断游戏节奏 · 全程不联网**

> **v2 与 v1 的根本区别**：v1 靠「屏幕截图 + OCR 认名字」，要校准三个监视区域，
> 认错字、错过画面都是常态。v2 改成读 **游戏内插件 HD2Tracker** 写出的日志文件 ——
> 名字与玩家标识都是插件从游戏名册里读出来的**原文**，没有识别误差，
> 也不需要框选任何区域。

## 1. 它是怎么工作的

| 做 | 不做 |
|---|---|
| 只读一个文本文件：插件写出的 `playerLog.txt` | ❌ 不注入游戏进程 |
| 本地 SQLite 比对本机黑名单（PeerID 精确 + 名字四层） | ❌ 不读游戏内存 |
| 无焦点分层窗口提示（每栏一个独立窗口） | ❌ 不修改 / 拦截网络包 |
| 把遇到过的队友收进「最近遇到」，方便一键入名单 | ❌ 不向游戏服务器发送任何请求 |
| 每秒一次 `os.stat` + 增量读 | ❌ 不截图、不 OCR、不装键盘钩子 |

提示窗口使用 `WS_EX_NOACTIVATE | WS_EX_TRANSPARENT | WS_EX_TOOLWINDOW | WS_EX_TOPMOST`：
**不抢焦点**（不会让你突然无法操作鼠标键盘）、鼠标点击会 **穿透** 提示窗口、
不出现在 Alt-Tab 列表里。

> ⚠️ 任何第三方自动化工具都可能违反游戏的服务条款（ToS）。是否使用请自行评估与承担。

### 版本历史

| 版本 | 主要变化 |

## 2. 下载与安装

### 前提：游戏内插件

本工具的数据 **全部** 来自游戏内插件 **HD2Tracker**（它把队里的名字与玩家标识写成
一个日志文件），所以需要两样东西：

1. **加载器 Bingus Shared Loader** —— HD2 的 addon 加载器，负责把插件挂进游戏；
2. **插件包 HD2Tracker** —— 单独的开源项目：
   [**NealDai06/HD2Tracker**](https://github.com/NealDai06/HD2Tracker)
   （源码、说明与 Releases 都在那边）。

**两个要一起用，缺一个都不工作**：插件在游戏里跑，把「这一局队里有谁」写成上面那个日志
文件；本工具读这个文件、比对本地名单，名单里的玩家进队时提醒你。
插件自己的安装、配置与已知限制见它仓库的 README。

> **插件从哪来 / 致谢**：插件在独立仓库
> [NealDai06/HD2Tracker](https://github.com/NealDai06/HD2Tracker)；它的**本体框架由
> [360de250/Helldivers2-SteamID-Tracker](https://github.com/360de250/Helldivers2-SteamID-Tracker)
> （mod 名 `kick`，MIT 许可）扩张而来**；在设计上**受
> [CowboyBingus/BetterLobbyManagement](https://github.com/CowboyBingus/BetterLobbyManagement)
> （0BSD 许可）启发**，并且借用了它标定的 `game.dll` 布局与代码签名来做自校验。
> 完整的出处说明与两份上游许可正文见 [THIRD_PARTY.md](THIRD_PARTY.md)。

装好后 **进一次游戏**，这个文件就会出现：

```
%LOCALAPPDATA%\CowboyBingus\Helldivers2\Logs\playerLog.txt
```

没出现的话不用猜 —— 打开本工具的「最近遇到」页，它会直接告诉你日志目录在不在、
文件有没有、插件版本够不够新。

### 方式 A：用打包好的版本（推荐）

1. 到 [Releases](https://github.com/NealDai06/HD2Blacklist/releases) 下载
   `HD2Blacklist-v2.0.0-win64.rar` 并解压；
2. **整个 `HD2Blacklist\` 文件夹一起放**到可写目录（桌面、`D:\` 都行）——
   只拷 exe 起不来（缺 `_internal\`）；
3. 双击 `HD2Blacklist.exe`。对方 **不需要装 Python**。

> 别放 `C:\Program Files`：程序要往自己的 `data\` 写名单，受保护目录会失败。
> 未签名的 exe 首次运行可能被 SmartScreen 拦 →「更多信息」→「仍要运行」。

**从 v1 升级**：直接把你旧的 `data\` 目录盖过来即可。首次打开会自动给名单加上
`peer_id` 列（老条目留空 = 继续按名字匹配），并把抓屏时代的 `encounters` 表删掉。

### 方式 B：从源码运行

```bat
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python main.py --check      :: 环境自检（强烈建议先跑一次）
python main.py
```

仓库自带的依赖目录（`.pylibs` / `.devtools`）由 `main.py` 启动时自动加进 `sys.path`，
**不需要手动设 `PYTHONPATH`**。

### 环境要求

| 项目 | 要求 |
|---|---|
| 操作系统 | Windows 10 / 11（64 位） |
| 游戏内插件 | Bingus Shared Loader + HD2Tracker **v21.2 或更新**（更老的版本字段对不上，界面会明说） |
| Python（仅方式 B） | 推荐 3.11 ~ 3.13（v2 不再需要 rapidocr / onnxruntime / opencv） |
| 权限 | 普通用户即可，不需要管理员 |

## 3. 快速开始

1. 按上面的「前提」把 **加载器 + 插件** 装好，进一次游戏确认 `playerLog.txt` 出现；
2. 启动本工具，打开 **「最近遇到」** —— 应该能看到刚才同队的人；
3. 选中一个 → **[加入名单]**（双击那一行也行）→ 想写备注就写，PeerID 已经填好了；
4. 以后他一进你的队，就会弹出无焦点提示。

首次启动会自动生成 `data/`（数据库、配置示例、默认图标、日志），
并附带 2 条 `SamplePlayer_0x` 示例数据，不需要就直接在界面里删掉。

## 4. 什么时候会提醒

**只有一种情况会提醒**：有人在你的队伍里 **刚进队**（插件写出 `join` 事件）、
不是你自己、并且 **PeerID 命中黑名单**。

| 情况 | 会不会提醒 |
|---|---|
| 有人刚进队（`join`）+ PeerID 命中 | ✅ 会 |
| 有人刚进队，但只有**名字**对得上 | ❌ **不会** —— 名字可以重名、可以随时改，拿它当身份会认错人 |
| 队伍快照刷新（`squad`） | ❌ 不会 —— 那是"现在队里有谁"的**状态**，拿它报警会把进队就在队里的人反复报一遍 |
| 同一个人的信息补齐（`update`） | ❌ 不会 |
| 有人离队（`leave`） | ❌ 不会（只在界面动态里留一行） |
| 你自己 | ❌ 永远不会被当成目标 |
| 在 **忽略名单** 里的人 | ❌ 不会（也不进「最近遇到」） |
| 同一局里 30 秒内重复进出的同一个人 | ❌ 只提醒第一次（去重窗口，默认 30 秒） |
| 换了一局又遇到 | ✅ 会重新提醒一次 |

**所以：名单里没有 PeerID 的条目不会提醒。** 这是有意的取舍 —— 名字当身份既会
认错人（别人取同名），也认不出改名。想让它生效有两条路：在「最近遇到」里
**重新加入**（会带上 ID），或者右键那条 → **[补全 PeerID]**。
从 v1 升级上来的名单默认**全是**这种条目，程序启动时会直接在「最近动态」里提醒你。

反过来说，有 PeerID 的条目 **改名也照样认得出** —— 这正是把它当主键的价值。

**名字还会自动同步。** 局内只要看到某个 PeerID 的名字和名单里写的不一样，
程序就 **把名单里的名字改成新的**（先改名、再弹提示，所以提示里显示的就是他现在的
名字），**旧名字同时记进「曾用名」列**。理由是：PeerID 才是身份，名字只是给人看的
显示名，写个过期名字只会让你对着名单认不出这是谁。改名这件事会在状态栏、
「最近动态」和日志里各留一行痕迹（自动改你的数据这件事，必须让你看得见）。
同一个人的名字 5 秒内最多同步一次，挡的是名册读取抖动造成的反复改名。

**曾用名**可以在 [编辑] 里自己改（多个用 `/` 分开），也可以清空；他自己改名时
程序会自动往里记（最多留最近 8 个）。它**只给人看** —— 不参与匹配、不参与告警。

**一次进队多人命中**：每人 **各自一个通知栏**（垂直堆叠、互不遮挡），**音效只播一次**；
超过 5 个时最后一栏换成汇总栏（`等 3 名：A、B、C`）。整批会写进 `data/logs/app.log`。

## 5. 界面一览

单页五段，**没有菜单栏**：

```
① 运行状态带  [图标] HD2 黑名单 v2.0.0  ● 追踪中  ● 追踪中 · 队伍 2 人 · 最近遇到 12 人
              [最近遇到] [暂停追踪] [退出]
② 名单工具带  [添加][编辑][删除]   搜索[__]   排序[__]↓   [导入][导出]
③ 名单主区    名称 | PeerID | 曾用名 | 备注 | 添加时间   （右侧留一条空白供拖宽最后几列）
═══ 分隔条（可上下拖动）═══════════════════════════════════════════════════════
④ 设置分页    [最近遇到][通知][数据][帮助]                            ▴ 展开设置
⑤ 状态栏      最近动态（3 行，带时间戳）+ 当前状态 + 统计
```

| 段 | 放什么 |
|---|---|
| ① 运行状态带 | 追踪灯（追踪中 / 已暂停）、一句话追踪状态、**[最近遇到]**、**[暂停追踪]**、**[退出]** |
| ② 名单工具带 | 增删改查、搜索、排序、导入导出 —— 只放"对这张名单的操作" |
| ③ 名单主区 | Treeview，占满剩余高度。`PeerID` 是**只读**的系统列，右键可复制；`曾用名` 是历史记录（可手填、可清空） |
| ④ 设置分页 | 四个分页，**默认收起** 成一条标签栏，点标签或 [展开设置] 打开；内容过高时内部可滚动 |
| ⑤ 状态栏 | 「最近动态」事件流 + 当前状态 + `黑名单总数 / 本局告警 / 最近遇到 / 当前队伍` |

- 名单区与设置区之间是 **可拖拽分隔条**，比例自己定；展开高度按当前页内容自适应
  （设置区最多占 60%，列表内容长时可以在设置区里滚动；把分隔条往上拖就给设置区腾地方）
- **列宽随便拖**：每一列都可以自己拉宽拉窄（右边留了一小条空白专门用来让位，
  所以最后一列也能往右拉宽）。右键名单 → **[列宽自适应]** 恢复默认宽度
- 关闭窗口 = 最小化到托盘（追踪继续），真正退出在 ① 最右侧或托盘菜单
- 追踪指示灯由 (日志里有没有游戏在跑, 用户是否暂停) **两个真值**渲染

「最近动态」是 **事件流**（3 行、`HH:MM:SS` 时间戳、最新在最上），按级别着色：
命中=绿 · 跳过/暂停=金 · 失败/告警=红 · 普通=灰。游戏启停、进入一局、有人进队/离队、
命中、通知弹不出来……都会留痕，不会被下一条提示覆盖。

**名单只有五个字段**：`player_name`（唯一）· `peer_id`（系统填写，只读）·
`prev_names`（曾用名，改名时自动记，也可以手填）· `note`（备注）· `created_at`（添加时间）。

## 6. 最近遇到 & 加入名单

这是 v2 最省事的地方：**不用手打任何 ID**。

展开设置区 **「最近遇到」** 分页：

```
追踪状态
  日志文件：C:\Users\…\CowboyBingus\Helldivers2\Logs\playerLog.txt
  文件状态：存在  大小 6377 字节  已读到偏移 6377
  插件版本：hd2trackerv21.2
  解析：成功 15 行  失败 0 行  重复丢弃 0 行
  游戏 PID：12345  我自己：Me  最后事件：join @ 2026-10-10 20:00:00
  当前队伍（2 人）：甲、乙

最近遇到（插件每读到一次名册就记一次；双击那一行 = 加入名单）
  玩家名 | PeerID | 最近遇到 | 遇到局数 | 状态
  [加入名单] [从列表移除] [忽略此人] [手动添加…]
```

| 按钮 | 语义 |
|---|---|
| **[加入名单]** | 把选中的人加进黑名单：名字与 PeerID 预填，你只写备注 |
| **[从列表移除]** | 只是把这一条从「最近遇到」划掉。**下次遇到他照旧记录、照旧提醒** |
| **[忽略此人]** | 记进 **忽略名单**：以后既不再提醒、也不再进列表 |
| **[手动添加…]** | 老路：手填名字（只能按名字匹配，没有 PeerID） |
| **[打开日志目录] / [打开 playerLog.txt]** | 直接开文件夹/文件，排查用 |

「遇到局数」的口径是 **遇到过几局**，不是写了几行日志 —— 同一局里他离队又回来只算一次。

右键名单里的老条目还有 **[补全 PeerID]**：从「最近遇到」里挑一个给他补上 ID。
补上之后这条才**会**告警（提醒只认 PeerID），而且改名字也照样认得出、
不会再被同名的人骗到。

## 7. 名单导入导出

顶部工具带右侧 **[导出]** / **[导入]**，用于备份、换机迁移、多机同步。

| 格式 | 编码 | 适用 |
|---|---|---|
| **CSV** | `utf-8-sig`（带 BOM） | Excel 直接双击打开 **不乱码**，也可用记事本编辑 |
| **JSON** | `utf-8` | 结构化，便于脚本处理与人工核对 |

导出字段：`player_name, note, peer_id, prev_names, created_at`（**PeerID 一起走**，导回来精确匹配照样有效；曾用名也不会丢）。

**导入的身份键：有 PeerID 就用 PeerID，没有才退回名字**（大小写不敏感）。
这条规矩决定了两种"看着像冲突、其实不是"的情况：

| 文件里的那一行 | 名单里已有 | 结果 |
|---|---|---|
| 同名、**不同 PeerID** | 有 | **两个人都留着** —— 同名不同人是两个人 |
| **同 PeerID**、名字不同 | 有 | 认出来是同一个人改了名 → **更新名单里的名字**（不分策略，因为"谁"是确定的） |
| 同 PeerID、名字相同 | 有 | 同一个人 → 按下面的策略处理 `note` / `created_at` |
| 两边都没有 PeerID、名字相同 | 有 | 按名字当成同一个人 → 按策略处理 |
| 文件里没有 PeerID，名单里那条**有** PeerID | 有 | 身份不同 → **各留一条**（有 ID 的那条不会被裸名字顶掉） |
| 都没有 | — | 新增一条 |

只有 **同一个身份键** 撞上时，才轮到策略决定备注/添加时间怎么办：

| 策略 | 行为 |
|---|---|
| **跳过已存在的条目**（默认） | 只新增；同一个人的 `note` / `created_at` 一个都不动 |
| **只更新备注** | 同一个人的 `note` 用文件里的覆盖，保留本机的 `created_at` |
| **完全覆盖** | `note` 与 `created_at` 都用文件里的值 |

完成后提示「新增 N，更新 K，跳过 J（PeerID 命中后改名 M）」。没有名字的行一律跳过；
老版本导出文件里多余的 `player_id` / `tk_count` 等字段 **一律无视**；
整个导入在 **一个事务** 内完成，任何一条出错就全部回滚；
导入导出都在后台线程执行，大文件不会卡界面。

**导入不会清空你的名单**：表既不删也不重建，只有"新增一行"和"改那一行的字段"两种动作。

> ⚠️ 导出文件里包含你的完整黑名单，注意保管。

## 8. 自定义提示

展开设置区 **「通知」** 分页：左侧四个子页（文案 / 图片 / 外观 / 音效），右侧 **实时预览**。

文案可用占位符：

| 占位符 | 含义 |
|---|---|
| `{player_name}` | 玩家名称 |
| `{match_score}` | 匹配度（PeerID 精确命中恒为 100） |
| `{note}` | 备注 |
| `{source}` | 命中来源（PeerID 精确命中 / 玩家名命中） |
| `{time}` | 当前时间 |

「字段显示开关」关掉的字段，**正文模板里只包含该字段的整行会被自动去掉**。

- **图片**：默认图 / 自定义图 / 不显示，可设显示尺寸。点 [浏览…] 时对话框默认停在
  `data/assets/`，选中后 **自动复制一份** 进去（原图以后移走、删掉也不影响），
  支持 `PNG / JPG / JPEG / BMP / GIF`
- **外观**：背景 / 文字 / 标题色、透明度、宽高、位置（7 种）、显示器、显示时长；
  标题与正文字号 **独立可调**（8~72 像素，默认 16 / 13，含 小 / 标准 / 大 / 特大 预设），
  字号变大或正文过长时窗口自动增高，**绝不截断文字**
- **音效**：`beep`（可调频率与时长）/ 自定义音频文件（`WAV · MP3 · OGG · FLAC`，可 [试听]）/ 静音。
  自定义音频同样会自动复制进 `data/assets/`；播放始终在独立线程
- **[实时预览]** 真的弹一次无焦点 Overlay；**[测试通知]** 用假数据完整走一遍

配置 `data/notification.json` 采用 **深合并**：只写想改的字段，其余自动用默认值；
JSON 写坏了会回退默认。手动编辑或直接删掉文件都 **无需重启**。

## 9. 数据文件

运行期数据都在 `data/` 下（首次启动自动生成）：

| 路径 | 说明 |
|---|---|
| `blacklist.db` | SQLite 数据库（WAL 模式）：名单 + 最近遇到 + 忽略名单 |
| `notification.json` | 提示外观、位置、音效 |
| `assets/` | 应用图标 + 你选的自定义提示图 / 音效（自动复制的副本） |
| `logs/app.log` | 运行日志（轮转，单文件上限 2 MB） |

**游戏内插件的日志在别处**（不受本程序管理，删了会被插件重新写出来）：
`%LOCALAPPDATA%\CowboyBingus\Helldivers2\Logs\playerLog.txt`

数据库三张表：

```sql
CREATE TABLE blacklist (              -- 名单：只回答"这个人要不要提醒"
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    player_name TEXT NOT NULL,        -- 显示名（**不是**身份）
    note TEXT DEFAULT '',
    peer_id TEXT DEFAULT '',          -- **身份**：PlayFab 账户标识，跨局稳定
    prev_names TEXT DEFAULT '',       -- 曾用名：JSON 数组，只给人看
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
-- 身份 = PeerID（部分索引：空串不参与唯一性，那些条目退回按名字）
CREATE UNIQUE INDEX idx_blacklist_peer
    ON blacklist(peer_id) WHERE peer_id <> '';
-- 没有 PeerID 的条目：名字仍然唯一（两条都没 ID 的同名记录分不清谁是谁）
CREATE UNIQUE INDEX idx_blacklist_name_legacy
    ON blacklist(player_name) WHERE IFNULL(peer_id,'') = '';

CREATE TABLE seen_players (           -- 「最近遇到」：插件日志喂进来的
    peer_id       TEXT PRIMARY KEY,
    name_first    TEXT DEFAULT '',    -- 第一次见到的名字
    name_last     TEXT DEFAULT '',    -- 最近一次见到的名字（改名跟着变）
    first_seen    DATETIME,
    last_seen     DATETIME,
    seen_count    INTEGER DEFAULT 1,  -- 遇到过几局
    last_game_pid INTEGER
);

CREATE TABLE ignored (                -- 忽略名单：不提醒、也不进最近遇到
    peer_id  TEXT PRIMARY KEY,
    name     TEXT DEFAULT '',
    added_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

**为什么是"部分索引"而不是普通的唯一索引**：SQLite 里空串也算一个值，
直接 `UNIQUE(peer_id)` 会让第二条"没有 ID 的条目"插不进去。用 `WHERE peer_id <> ''`
把没有 ID 的行排除在唯一性之外，它们改走名字那条索引。

`blacklist` 里 **没有任何人均统计字段**（v1.1.2 就删掉了 玩家ID / TK次数 / 遇到次数 /
最后遇见）。**老库首次打开会自动升级**，按顺序做几件事：名称栏为空的条目用玩家ID补成
名字（不丢条目）、同名只留第一条、补上 `peer_id` / `prev_names` 两列（一律留空）、
**把"名字唯一"换成"PeerID 唯一"**、删掉抓屏时代的 `encounters` 表；
每一步都往日志里写一行说明。名单里的名字与备注一个都不会丢。

> 曾用名在库里存的是一串 **JSON 数组**（`["老王", "老王2"]`），不是分隔符拼的字符串 ——
> 玩家名里可能有逗号/斜杠，用分隔符会切碎。导出到 CSV/JSON 时原样带走，导入时原样带回来。

**可安全删除**（会自动重建）：`build/`、`.test_tmp/`、任意 `__pycache__/`。
**绝不能删**：`data/`、`../_packaged_data_backup/`、`.pylibs/`、`.devtools/`、`使用说明.txt`。

所有 `data/*.json` 都支持手动编辑或直接删除恢复默认，改动无需重启。

## 10. 常见问题

**Q：界面一直说「未找到插件日志」？**
三件事按顺序查：① 加载器与插件装了没；② 装好后 **进过一次游戏没**（插件只在游戏里跑）；
③ 看加载器自己的日志 `%LOCALAPPDATA%\CowboyBingus\Helldivers2\Logs\BingusSharedLoader.log`，
里面 `load failed: <文件>:<行>: <错误>` 就是插件没加载成功的原因。另一个文件
`playerLog.log` 是插件的诊断日志，能看到它自己认为发生了什么。

**Q：提示「插件版本过旧」？**
插件字段在不同版本里不一样（老版本没有 `peer_id_hex` / `capture_id`）。更新插件到
**hd2trackerv21.2 或更新**即可；界面会写明当前版本与要求的版本。

**Q：明明遇到记录在案的人，却没提醒？**
按顺序看：① **名单里那条有没有 PeerID** —— 没有就**不会提醒**（这是最常见的原因，
尤其是刚从 v1 升上来的名单），右键它 → [补全 PeerID]，或在「最近遇到」里重新
[加入名单]；② 他是不是 **刚进队**（`join`）——如果他在你打开程序之前就已经在队里，
只有「最近遇到」会记他，不会有提醒（提醒是事件驱动的）；③ 他是不是在 **忽略名单** 里；
④ 是不是同一局里 30 秒内已经提醒过一次；⑤ 打开 `data/logs/app.log` 搜 `[命中]`，
命中过就会有一行。

**Q：为什么我的老条目（只有名字）不提醒了？**
因为**提醒只认 PeerID**，而你的老条目里没有 ID。名字不能当身份：别人取同名就会
误报，他改个名字你就认不出来了。补上 ID 的办法有两个 —— 在「最近遇到」里找到他
→ [加入名单]（名字和 ID 都由程序填好），或者右键那条 → [补全 PeerID]。
启动时程序会在「最近动态」里直接告诉你还有几条这样的条目。

**Q：我给他补了 ID、他改了名字，还认得出来吗？**
认得。PeerID 是账户标识，跟显示名无关 —— 他改名之后你还是会收到提醒，
而且**名单里的名字会被自动改成他的新名字**（局内一看到他、名字和名单不一致就会改），
所以你不用手动维护。自动改名会在状态栏、「最近动态」和 `app.log` 各留一行痕迹。

**Q：名单里的名字怎么自己变了？**
那是**名字自动同步**：局内看到某个 PeerID 的名字和名单里写的不一样，程序就把名单
改成新的（PeerID 是身份，名字只是显示名，写个过期名字只会让你认不出这是谁），
旧名字同时记进 **「曾用名」列**。只有**带 PeerID 的条目**会被自动改，
而且同一个人 5 秒内最多改一次。想手动改回来：右键那条 → [编辑]；
曾用名那一栏也可以自己编辑/清空（多个用 `/` 分开）。

**Q：会拖游戏帧数吗？**
不会。v2 只做两件事：每秒一次 `os.stat`，以及文件变长时增量读那几十个字节。
不截图、不 OCR、不碰 GPU。程序仍然把自身进程压到 `below_normal`、
追踪线程压到 `lowest`，游戏永远优先拿 CPU。

**Q：玩家名就是一个问号 `？` / `?`，怎么不响应？**
提醒只认 PeerID，所以这类名字只要**补上 ID** 就能正常提醒。名字匹配那一套
（含全角半角折叠、符号层）还留在代码里，但只服务于离线排查
（`--replay` / `--check`），不再参与线上告警。

**Q：一次命中好几个玩家，只看见一个通知栏？**
每个堆叠槽位一个独立窗口，N 个玩家并排 N 栏，音效仍只播一次，
超过 5 个时最后一栏是汇总栏。完整名单也会写进 `data/logs/app.log`。

**Q：误报太多？**
现在几乎不可能因为"名字像"而误报 —— 告警只认 PeerID，同名不同人不会被算进来。
真遇到误报，先确认那条的 PeerID 是不是挂错了（名单里能看到完整 ID），
或者直接把它丢进 **忽略名单**。

**Q：导入会不会覆盖我现在的数据？**
不会清空名单，也**不会因为同名就跳过** —— 同名不同 PeerID 是两个人，两条都留；
同一个 PeerID 换了名字才会更新名字。只有"同一个身份"撞上时才按策略处理备注
与添加时间，默认 **跳过**（什么都不改）；且整个导入是单事务，中途出错全部回滚。

**Q：点了关闭窗口，程序去哪了？**
默认 **最小化到系统托盘**，追踪继续运行。点 ① 的 **[退出]** 或托盘菜单「退出」
才会真正结束。**暂停追踪** 期间发生的事不会补报 —— 这是"别打扰我"的意思。

**Q：不小心双击了好几次，会开出好几个进程吗？**
不会。命名内核互斥体保证单实例：再启动会把已有窗口叫到前台，第二个进程直接退出。
`--check` 等诊断命令不受此限制。

**Q：怎么彻底重置？**
删掉整个 `data/` 目录，下次启动自动重建（随包图标会自动补回来）。
想连"遇到过谁"一起清掉就在「数据」页点 **[清空「最近遇到」]**。

**Q：托盘图标不出现？**
需要 `pystray`；安装失败时状态栏会提示「系统托盘不可用」，其它功能正常。

## 11. 从源码运行与开发

### 自检与调试

```bat
python main.py --check                 :: 环境自检，逐项 OK/FAIL（退出码 0=通过）
```

`--replay` 拿一份日志离线复现"当时会告警几次"。以上诊断命令 **不受单实例限制**，
程序开着也能跑。

### 匹配策略

**身份 = PeerID**（`check_peer()`）：插件给的 `peer_id_hex` 是 PlayFab 的
`title_player_account`，跨局稳定、改名字也不变，缓存里 O(1) 命中。
**告警只走这一条路** —— 没有 PeerID 的条目不会告警。

名字匹配那一套（四层，见下）**不再参与告警**，只留给离线排查
（`--replay` / `--check` / 单元测试）：名字会重名、会随时改，拿它当身份既会认错人，
也认不出改名。

1. 整段文本归一化后检查黑名单名字是否为子串 → 100 分
2. 分词 + 相邻 2/3 词组合归一化后完全相等 → 100 分
3. 易混字符容错（`0↔O`、`1↔l↔I`、`5↔S`、`8↔B`、`2↔Z`、`4↔A`）→ 100 分
   （仅当该折叠键在黑名单中 **唯一** 时才生效）
4. 否则用 `rapidfuzz.ratio` 比对，**≥ 85** 才返回
5. **符号层**：名字整条就是符号时，只按"整段相等 / 某片段就是该符号串"匹配

归一化 = `NFKC` 折叠（全角 `？` → 半角 `?`）→ 转小写 → 去掉所有非字母数字字符，
所以 `Player_X` 与 `PlayerX` 能精确命中。**精确永远优先于模糊。**

## 12. 隐私

- 名单、最近遇到、忽略名单、提示图与音效 **只存在本机** `data/` 下；
  程序 **不联网、不上传任何东西**；

  打包后再扫一遍强制清空；

- 文档与测试里的玩家名一律是中性占位符（`PlayerX` / `SamplePlayer_01`），
  `LICENSE` 与 `使用说明.txt` 里的 `NealDai06` 是作者署名；
- 配套插件在独立仓库 [NealDai06/HD2Tracker](https://github.com/NealDai06/HD2Tracker)，
