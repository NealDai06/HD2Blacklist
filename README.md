# HD2 黑名单 · 绝地潜兵2 TK 者黑名单提示工具

**当前版本：v1.1.3** · Windows 10 / 11（64 位）· [MIT 许可](LICENSE)

一个 **纯本地** 的 Windows 桌面小工具：用 **屏幕截图 + OCR + 本地黑名单比对** 监视
《绝地潜兵2》(Helldivers 2) 的聊天框与玩家列表，在你遇到记录在案的 TK 玩家时，
用 **不抢焦点** 的音效 + 半透明 Overlay 小窗提醒你。

> **不注入进程 · 不读内存 · 不改包 · 不抢焦点 · 不打断游戏节奏 · 全程不联网**

## 1. 它是怎么工作的

| 做 | 不做 |
|---|---|
| 屏幕截图（mss） | ❌ 不注入游戏进程 |
| 本地 OCR（RapidOCR / onnxruntime） | ❌ 不读写游戏内存 |
| 本地 SQLite 比对（rapidfuzz） | ❌ 不修改 / 拦截网络包 |
| 无焦点分层窗口提示 | ❌ 不向游戏服务器发送任何请求 |
| 全局 `GetAsyncKeyState` 轮询 ESC、`RegisterHotKey` 注册扫描键 | ❌ 不安装键盘钩子（Hook）、不注入进程 |

提示窗口使用 `WS_EX_NOACTIVATE | WS_EX_TRANSPARENT | WS_EX_TOOLWINDOW | WS_EX_TOPMOST`：
**不抢焦点**（不会让你突然无法操作鼠标键盘）、鼠标点击会 **穿透** 提示窗口、
不出现在 Alt-Tab 列表里。

> ⚠️ 任何第三方自动化工具都可能违反游戏的服务条款（ToS）。是否使用请自行评估与承担。

### 版本历史

| 版本 | 主要变化 |
|---|---|
| **v1.1.3** | "扫描功能失效"的真因修复：源码运行没带上仓库自带的 `.pylibs`/`.devtools` → OCR 全程不可用，而旧代码只返回空结果，于是每轮扫描都"识别 0 个名字"，看着就像扫描坏了。现在启动时自动补路径，OCR 一旦不可用 **当场在界面写明原因**，不再假装"聊天框为空" |
| **v1.1.2** | **名单简化**：删掉 玩家ID / TK次数 / 遇到次数 / 最后遇见，只留 **名称 / 备注 / 添加时间**（老库首次打开自动升级，名字不丢，历史统计清空） |
| **v1.1.1** | 修复符号名（`？`）条目被静默丢弃导致的漏检；新增状态栏「最近动态」事件流；自定义快捷键面板不再显示过期的启用状态 |
| **v1.1.0** | 界面重排为单页五段；修掉两个"点了没反应"的开关；按钮在深色面板上可见化；打包不再携带任何用户数据 |
| v1.0.0 | 首个版本：四层匹配、ESC 菜单扫描、聊天框按需扫描 + 全局热键、无焦点 Overlay、区域校准、托盘常驻 |

## 2. 下载与安装

### 方式 A：用打包好的版本（推荐）

1. 到 [Releases](https://github.com/NealDai06/HD2Blacklist/releases) 下载
   `HD2Blacklist-v1.1.3-win64.rar` 并解压；
2. **整个 `HD2Blacklist\` 文件夹一起放**到可写目录（桌面、`D:\` 都行）——
   只拷 exe 起不来（缺 `_internal\`）；
3. 双击 `HD2Blacklist.exe`。对方 **不需要装 Python**。

> 别放 `C:\Program Files`：程序要往自己的 `data\` 写名单和截图，受保护目录会失败。
> 未签名的 exe 首次运行可能被 SmartScreen 拦 →「更多信息」→「仍要运行」。
> 到了新机器 **必须重新校准** 三个区域（坐标跟分辨率、UI 缩放绑定）。

### 方式 B：从源码运行

```bat
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python main.py --check      :: 环境自检（强烈建议先跑一次）
python main.py
```

仓库自带的依赖目录（`.pylibs` / `.devtools`）由 `main.py` 启动时自动加进 `sys.path`，
**不需要手动设 `PYTHONPATH`**。

### 环境要求

| 项目 | 要求 |
|---|---|
| 操作系统 | Windows 10 / 11（64 位） |
| 游戏显示模式 | **必须是无边框窗口（Borderless Windowed）** —— 全屏独占下截图会是黑屏、Overlay 也画不上去 |
| Python（仅方式 B） | 推荐 3.10 ~ 3.12；3.13 实测可用（`requirements.txt` 里按版本分流了 OCR 依赖） |
| 权限 | 普通用户即可；WMI 事件订阅需要管理员，权限不足时自动降级为 5 秒轮询，并在日志里写明 |

## 3. 快速开始

1. 游戏里把显示模式设成 **无边框窗口**；
2. 展开下方「监视区域」分页 → **[框选新区域]**，依次框选三个监视区域；
3. 点 **[添加]** 录入你要记的玩家名（只有 名称 / 备注）；
4. 启动游戏 —— 检测到 `helldivers2.exe` 后监视自动激活；
5. 想扫聊天框时点顶部 **[扫描聊天框]**（或按 F8，需先在「扫描与触发」里启用）。

首次启动会自动生成 `data/`（数据库、配置示例、默认图标、`evidence/`、日志），
并附带 2 条 `SamplePlayer_0x` 示例数据，不需要就直接在界面里删掉。

## 4. 什么时候会扫描

共三个触发源：

| 触发源 | 说明 |
|---|---|
| **聊天框（按需）** | 顶部 **[扫描聊天框]** 按钮，或自定义全局热键（默认 F8，需先启用）。**不点就零开销**：没有定时器、没有后台轮询；连点不会并发跑 OCR，会立刻返回"上一次扫描尚未完成" |
| **ESC 菜单** | 每 100 ms 轮询 `GetAsyncKeyState(VK_ESCAPE)`（**不是键盘钩子**），只在上升沿触发，判定菜单真的打开才启动扫描会话 |
| **冷启动** | 检测到游戏启动后 **12 秒** 自动扫一次 HUD 玩家列表 |

聊天框热键用 `RegisterHotKey` 注册成 **系统全局热键**：由系统投递 `WM_HOTKEY`，
与前台窗口无关，所以游戏在前台全屏也有效（这正是它比按键轮询可靠的地方）。
注册成功后该键被系统 **独占**，请避开游戏内按键；万一被别的程序占用，
会自动退回按键轮询模式并在状态栏写明原因。ESC 已被菜单扫描占用，不允许绑定。

**命中去重（30 秒）**：同一玩家在 30 秒内只记一次 `encounters`、只弹一次提示 ——
可以放心连点扫描。缓存只在内存里，也可以在「扫描与触发」页 **[清空命中去重缓存]**。

**扫描会话**（ESC / 冷启动）满足任一条件即终止：

| 终止条件 | 默认值 |
|---|---|
| 连续 N 次识别不到有效结果 | ESC 4 次 / 冷启动 3 次 |
| 总时长上限 | ESC 8 秒 / 冷启动 15 秒 |
| 距上一次发现新名字超过 X 秒 | ESC 3.5 秒 / 冷启动 0 秒（扫到就收工） |

同一时刻最多一个活跃会话，再次触发会先终止旧会话。

**一次命中多个玩家**：每个玩家 **各自一个通知栏**（垂直堆叠、互不遮挡），
**音效只播一次**；超过 5 个时最后一栏换成汇总栏（`等 3 名：A、B、C`），
保证"命中了谁"永远看得见。整批名单会写进 `data/logs/app.log`，方便事后核对。

## 5. 界面一览

单页五段，**没有菜单栏**：

```
① 运行状态带  [图标] HD2 黑名单 v1.1.3  ● 监控中   [启用 F8 扫描] [扫描聊天框] [暂停监控] [退出]
② 名单工具带  [添加][编辑][删除]   搜索[__]   排序[__]↓   [导入][导出]
③ 名单主区    名称 | 备注 | 添加时间
═══ 分隔条（可上下拖动）═════════════════════════════════════════════════
④ 设置分页    [扫描与触发][通知][监视区域][数据][帮助]              ▴ 展开设置
⑤ 状态栏      最近动态（3 行，带时间戳）+ 当前状态 + 统计
```

| 段 | 放什么 |
|---|---|
| ① 运行状态带 | 监控灯、**[启用/停用 F8 扫描]**、**[扫描聊天框]**、**[暂停监控]**、**[退出]**。按钮文字写的就是"点下去会发生的事" |
| ② 名单工具带 | 增删改查、搜索、排序、导入导出 —— 只放"对这张名单的操作" |
| ③ 名单主区 | Treeview，占满剩余高度 |
| ④ 设置分页 | 五个分页，**默认收起** 成一条标签栏，点标签或 [展开设置] 打开；内容过高时内部可滚动 |
| ⑤ 状态栏 | 「最近动态」事件流 + 当前状态 + `黑名单总数 / 本局命中 / 今日命中` |

- 名单区与设置区之间是 **可拖拽分隔条**，比例自己定；展开高度按当前页内容自适应
- 关闭窗口 = 最小化到托盘（监控继续），真正退出在 ① 最右侧或托盘菜单
- 监控指示灯由 (游戏在跑, 用户暂停) **两个真值**渲染，不会出现「游戏没开却显示监控中」

「最近动态」是 **事件流**（`EVENT_ROWS = 3` 行、`HH:MM:SS` 时间戳、最新在最上），
按级别着色：命中=绿 · 去重跳过=金 · 失败/告警=红 · 普通=灰。按 F8 / 点按钮触发的扫描、
命中、去重跳过、失败、游戏启停、扫描会话结束都会留痕，不会再被下一条提示覆盖。

**名单只有三个字段**（v1.1.2 起）：`player_name`（唯一，匹配只看它）· `note`（备注）·
`created_at`（添加时间）。命中的事实完整保留在 `encounters` 表与 `evidence/` 截图里，
底部的「本局命中 / 今日命中」是现算的。

## 6. 校准监视区域

展开设置区 **「监视区域」** 分页：

| 区域键 | 用途 |
|---|---|
| `chat_event` | 聊天框事件区域（玩家加入 / 离开的提示文字） |
| `player_list_hud` | HUD 玩家列表（任务中显示的队友名） |
| `menu_player_list` | ESC 菜单玩家列表（按 ESC 后左上角玩家信息） |

**[框选新区域]**（屏幕变暗、按住左键拖拽、实时显示 `x / y / 宽×高`、ESC 取消）·
**[恢复默认]** · **[恢复全部默认]** · **[实时预览]**（立刻截一张，确认框得对不对）。

默认坐标以 **1920×1080 无边框窗口、UI 缩放 100%** 为基准：

```json
{
  "chat_event":       {"left": 20, "top": 720, "width": 420, "height": 160},
  "player_list_hud":  {"left": 40, "top": 200, "width": 400, "height": 120},
  "menu_player_list": {"left": 60, "top": 120, "width": 500, "height": 300}
}
```

其它分辨率 / UI 缩放比例 **必须重新校准**。坐标保存在 `data/user_config.json`，
支持多显示器（含负坐标）；程序开启 Per-Monitor DPI 感知，保证截图区域与
Overlay 位置在缩放显示器上依然准确。

## 7. 名单导入导出

顶部工具带右侧 **[导出]** / **[导入]**，用于备份、换机迁移、多机同步。

| 格式 | 编码 | 适用 |
|---|---|---|
| **CSV** | `utf-8-sig`（带 BOM） | Excel 直接双击打开 **不乱码**，也可用记事本编辑 |
| **JSON** | `utf-8` | 结构化，便于脚本处理与人工核对 |

导出字段：`player_name, note, created_at`。导入以 **玩家名** 为唯一键
（大小写不敏感），冲突策略三选一：

| 策略 | 行为 |
|---|---|
| **跳过已存在的条目**（默认） | 只新增本机没有的名字；同名跳过 |
| **只更新备注** | 同名条目覆盖 `note`，保留本机的 `created_at` |
| **完全覆盖** | `note` 与 `created_at` 都用文件里的值 |

完成后提示「新增 N，更新 M，跳过 K」。没有名字的行一律跳过；老版本导出文件里
多余的 `player_id` / `tk_count` 等字段 **一律无视**；整个导入在 **一个事务** 内完成，
任何一条出错就全部回滚；导入导出都在后台线程执行，大文件不会卡界面。

> ⚠️ 导出文件里包含你的完整黑名单，注意保管。

## 8. 自定义提示

展开设置区 **「通知」** 分页：左侧四个子页（文案 / 图片 / 外观 / 音效），右侧 **实时预览**。

文案可用占位符：

| 占位符 | 含义 |
|---|---|
| `{player_name}` | 玩家名称 |
| `{match_score}` | 匹配度（0-100） |
| `{note}` | 备注 |
| `{source}` | 命中来源（chat / esc_menu / cold_start …） |
| `{time}` | 当前时间 |

「字段显示开关」关掉的字段，**正文模板里只包含该字段的整行会被自动去掉**。

- **图片**：默认图 / 自定义图 / 不显示，可设显示尺寸。点 [浏览…] 时对话框默认停在
  `data/assets/`，选中后 **自动复制一份** 进去（原图以后移走、删掉也不影响），
  支持 `PNG / JPG / JPEG / BMP / GIF`
- **外观**：背景 / 文字 / 标题色、透明度、宽高、位置（7 种）、显示器、显示时长；
  标题与正文字号 **独立可调**（8~72 像素，默认 16 / 13，含 小 / 标准 / 大 / 特大 预设），
  字号变大或正文过长时窗口自动增高，**绝不截断文字**
- **音效**：`beep`（可调频率与时长）/ 自定义音频文件（`WAV · MP3 · OGG · FLAC`，可 [试听]）/ 静音。
  自定义音频同样会自动复制进 `data/assets/`；播放始终在独立线程，不阻塞扫描
- **[实时预览]** 真的弹一次无焦点 Overlay；**[测试通知]** 用假数据完整走一遍

配置 `data/notification.json` 采用 **深合并**：只写想改的字段，其余自动用默认值；
JSON 写坏了会回退默认。手动编辑或直接删掉文件都 **无需重启**。

## 9. 数据文件

运行期数据都在 `data/` 下（首次启动自动生成）：

| 路径 | 说明 |
|---|---|
| `blacklist.db` | SQLite 数据库（WAL 模式），名单 + 命中事实 |
| `user_config.json` / `notification.json` / `hotkey.json` | 监视区域、提示外观、扫描热键 |
| `assets/` | 应用图标 + 你选的自定义提示图 / 音效（自动复制的副本） |
| `evidence/` | 命中证据截图（自动清理，默认保留 500 张） |
| `logs/app.log` | 运行日志（轮转，单文件上限 2 MB） |

数据库只有两张表：

```sql
CREATE TABLE blacklist (              -- 名单：只回答"这个名字要不要提醒"
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    player_name TEXT NOT NULL,        -- 匹配只看它，唯一
    note TEXT DEFAULT '',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
CREATE UNIQUE INDEX idx_blacklist_name ON blacklist(player_name);

CREATE TABLE encounters (             -- 命中事实：一次命中一行
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    blacklist_id INTEGER,
    name_seen TEXT,
    match_score REAL,
    source TEXT,
    screenshot_path TEXT,
    seen_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

`blacklist` 里 **没有任何人均统计字段**（v1.1.2 删掉了 玩家ID / TK次数 / 遇到次数 /
最后遇见），命中事实全在 `encounters`。**老库首次打开会自动升级**：名称栏为空的条目
用玩家ID补成名字（不丢条目）、同名只留第一条、`encounters` 清空、证据截图不碰，
并往日志里写一行 WARNING 说明保留 / 丢弃了多少条。

**可安全删除**（会自动重建）：`build/`、`.test_tmp/`、任意 `__pycache__/`。
**绝不能删**：`data/`、`../_packaged_data_backup/`、`.pylibs/`、`.devtools/`、`使用说明.txt`。

所有 `data/*.json` 都支持手动编辑或直接删除恢复默认，改动无需重启。

## 10. 常见问题

**Q：截图是黑的 / Overlay 不显示？**
游戏必须是 **无边框窗口** 模式 —— 全屏独占下 Windows 会屏蔽其它窗口与截图。

**Q：一触发扫描，游戏的最低帧（1% low）就掉到 55 之类？**
两个原因：① 抓屏 + OCR 是一次性吃 CPU 的活，默认已把本进程压到 `below_normal`、
扫描线程压到 `lowest`（`GAME_FRIENDLY_PRIORITY`），游戏始终优先拿 CPU；
② GDI 截屏要让 GPU/DWM 同步，**抓屏次数 ≈ 卡顿次数**，默认已把菜单会话抓屏间隔
放宽到 0.5 s、画面静止 6 帧即收工、画面没变就不重复 OCR。
想更省：把 `config.py` 里的 `OCR_UPSCALE` 从 2 降到 1（识别像素少 4 倍），
或把 `ESC_SESSION["interval"]` 放宽到 0.8~1.0 —— 想去掉哪个再试哪个，
`python tools/perf_probe.py` 会实测抓屏 / OCR 各花多少 CPU 与墙钟。

**Q：识别不到玩家名？**
① 先跑 `python main.py --capture-debug`，打开 `data/logs/debug_<区域>.png` 确认区域
是否真的覆盖了文字；② 重新框选，**只框文字本身**，别框进大片背景；
③ 跑 `python main.py --check` 看 **「监视区域尺寸」** —— 被框成 10×13 像素这种
永远识别不到，自检会点名；④ 小字号、低对比度识别率会下降，可适当放大游戏 UI。

**Q：扫描"能用"但什么都识别不到？**
先看「最近动态」和 `app.log` 里有没有 **OCR 不可用** 这几个字。有 → 是运行环境
缺 rapidocr（用 `python main.py` 启动会自动补路径，或直接用打包版）；没有 → 是
聊天框区域没框对。OCR 不可用时程序会 **当场说明原因**，不会假装"聊天框为空"。

**Q：游戏里按 F8 没反应？**
① 确认 ① 状态带上的按钮已经是金色的 **[停用 F8 扫描]**（点一下切换）；
② 看状态栏写着「已注册为系统全局热键」还是「退回按键轮询模式」—— 被别的程序
占用（录屏、外设驱动）就换个键；③ `python tools/hotkey_probe.py` 可做真机探测。

**Q：为什么同一个玩家只提示了一次？**
命中有 **30 秒去重窗口**（窗口内既不弹窗也不记 `encounters`）。想立刻重新计，
用「扫描与触发」→ **[清空命中去重缓存]**；「最近动态」会写明"30 秒内刚提示过 → 跳过"。

**Q：玩家名就是一个问号 `？` / `?`，怎么不响应？**
现在支持了：全角半角等价（NFKC 折叠），走独立的 **符号层**、**只按整体相等** 匹配
（所以聊天里打 `???` 或 `?!` 不会误报），OCR 名字过滤器也带黑名单白名单放行。
`python main.py --check` 的 **「全符号玩家名」** 一项会验证这条链路。

**Q：ESC 菜单里明明有玩家名，却什么都没检出？**
早期版本判定"菜单是否打开"用的阈值正好压在真实截图中间，一半概率被判成"没开"
而根本不扫描；已改为看 **平均亮度**（暗色面板 = 菜单开着），判不准还会复查 3 次、
最后宁可按开着处理。升级到本版本即可，不需要改配置。

**Q：一次命中好几个玩家，只看见一个通知栏？**
早期所有通知栏共用 **一个** 分层窗口，后画的会把先画的整个盖掉。现在每个堆叠槽位
一个独立窗口，N 个玩家并排 N 栏，音效仍只播一次，超过 5 个时最后一栏是汇总栏。
完整名单也会写进 `data/logs/app.log`。

**Q：误报太多？**
`config.py` 里的 `MATCH_THRESHOLD`（默认 85）可以提高；另外尽量录入 **完整玩家名**，
2~3 个字母的短名容易模糊命中。

**Q：导入会不会覆盖我现在的数据？**
取决于所选策略，默认 **跳过**（什么都不覆盖）；且整个导入是单事务，中途出错全部回滚。

**Q：点了关闭窗口，程序去哪了？**
默认 **最小化到系统托盘**，监控继续运行。点 ① 的 **[退出]** 或托盘菜单「退出」
才会真正结束。

**Q：不小心双击了好几次，会开出好几个进程吗？**
不会。命名内核互斥体保证单实例：再启动会把已有窗口叫到前台，第二个进程直接退出；
进程被强杀 / 崩溃也不会留下"锁文件删不掉"的问题。`--check` 等诊断命令不受此限制。

**Q：怎么彻底重置？**
删掉整个 `data/` 目录，下次启动自动重建（随包图标会自动补回来）。

**Q：托盘图标不出现？**
需要 `pystray`；安装失败时状态栏会提示「系统托盘不可用」，其它功能正常。

## 11. 从源码运行与开发

### 自检与调试

```bat
python main.py --check                 :: 环境自检，逐项 OK/FAIL（退出码 0=通过）
python main.py --capture-debug         :: 抓三个区域 + OCR，截图写到 data/logs/
python main.py --preview-notification  :: 离线渲染一张通知预览图（不需要显示器）
python main.py --debug                 :: 打开 DEBUG 日志
```

坐标或识别效果不确定时，**先跑 `--capture-debug` 打开 PNG 人工确认** 再调整。
以上诊断命令 **不受单实例限制**，程序开着也能跑。

### 打包

```bat
python build.py --clean              :: 文件夹版（推荐：启动约 1 秒）
python build.py --clean --onefile    :: 单文件版（便携，启动要解压 5~15 秒）
python build.py --console            :: 保留控制台，排查问题用
python build.py --clean --keep-data  :: 保留产物里已有的 data/（开发自用）
```

产物写到 **上一层的 `发布包/`**，并在 exe 旁边放好 `data/` 种子目录、`使用说明.txt`
与 `LICENSE.txt`。

**打包不带任何用户数据**：`data/` 里的名单、证据截图、区域坐标、你自己挑的提示图与
音效 **一个字节都不进产物** —— 只带三个图标，其余由程序首次运行生成；
`--clean` 时旧产物的 `data/` 会整体 **备份**（只搬不删）到
`../_packaged_data_backup/packaged_<时间戳>/`。`build.py` 同时排除了
`torch` / `transformers` / `matplotlib` 等无关大块头（onnxruntime 的可选后端会把
整个 PyTorch 拖进来，实测多出约 500 MB），文件夹版因此从 817 MB 降到 **288 MB**。

分发时注意：**整个文件夹一起拷** · 放在 **可写目录** · 目标系统 **Win 10/11 64 位** ·
到新机器 **必须重新校准三个区域** · SmartScreen 提示走「更多信息 → 仍要运行」·
打包版没有控制台，想跑自检用 `start /wait HD2Blacklist.exe --check` 再读 `data\logs\app.log`。

### 匹配策略（先精确，再易混，再模糊，最后符号层）

1. 整段文本归一化后检查黑名单名字是否为子串 → 100 分（覆盖多词名字被标点切散）
2. 分词 + 相邻 2/3 词组合归一化后完全相等 → 100 分
3. OCR 易混字符容错（`0↔O`、`1↔l↔I`、`5↔S`、`8↔B`、`2↔Z`、`4↔A`）→ 100 分
   （仅当该折叠键在黑名单中 **唯一** 时才生效）
4. 否则用 `rapidfuzz.ratio` 比对，**≥ 85** 才返回
5. **符号层**：名字整条就是符号时，只按"整段相等 / 某片段就是该符号串"匹配

归一化 = `NFKC` 折叠（全角 `？` → 半角 `?`）→ 转小写 → 去掉所有非字母数字字符，
所以 `Player_X` 与聊天框里的 `PlayerX` 能精确命中。**精确永远优先于模糊**；
OCR 拆行的碎片会按纵向重叠 + 横向间距拼回整名；`小队`、`185级|功勋英雄`
这类 UI 文字会被过滤掉。
