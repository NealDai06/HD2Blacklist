HD2 黑名单 v2.0.0 —— 使用说明
================================================================

【这一版（v2.0.0）改了什么】
  · 数据来源整个换掉了：不再截图 + OCR，改成读**游戏内插件**写出的日志文件。
      老办法要你先框选三个监视区域，靠识别屏幕上的字来认人 —— 认错字、
      跳过一帧都会漏人，换个分辨率还得重新框一遍。
      现在名字和玩家标识都是插件从游戏名册里读出来的**原文**，
      没有识别误差，也不需要框任何区域。
  · 名单多了一栏 **PeerID**（只读，程序自己填）：
      它是 PlayFab 的账户标识，**跨局稳定、改名字也不变**，所以它是**身份**：
        · 同名、不同 PeerID  → 是两个人 → 两条都留着
        · 同一个 PeerID 换了名字 → 是同一个人 → 只更新名字
      提醒也**只认 PeerID** —— 名字会重名、会随时改，拿它当身份会认错人。
      ⚠ 没有 PeerID 的条目**不会提醒**（从 v1 升上来的名单默认全是这种），
        补 ID 的办法见下面「老条目不提醒了？」
      ⚠ 这一栏**不给你手打** —— 以前"把名字填进 ID 栏"那种错，结构上不可能再发生。
  · **名字会自动同步 + 自动记曾用名**：局内看到某个人（在名单里、有 PeerID）的
      名字和名单里写的不一样，程序就**把名单里的名字改成他现在的名字**，
      同时把**旧名字记进「曾用名」栏** —— 先改名、再弹提示，所以提示里显示的
      就是新名字。自动改完之后状态栏、「最近动态」和日志里都会留一行痕迹
      （改你的数据，必须让你看得见）。同一个人的名字 5 秒内最多同步一次。
  · 新增 **「最近遇到」**：和游戏一起跑，插件每读到一次名册就把队里的人记下来。
      想拉黑谁：打开这一页 → 选中那一行 → [加入名单]（双击也行）→
      名字和 PeerID 已经填好了，你只写备注。不用打任何 ID。
  · 新增 **忽略名单**：有些人你不想再看到提醒，但他又不配进黑名单 ——
      选中 → [忽略此人]，以后既不再提醒、也不再出现在「最近遇到」里。
      反悔的入口在「数据」页 → [忽略名单…]。
  · 下线的东西：屏幕截图、OCR、监视区域校准、扫描热键、ESC 菜单扫描、
      冷启动扫描、证据截图（以及对应的依赖 rapidocr / onnxruntime / opencv /
      wmi / pywin32）。程序因此比自己 v1 的时候更小、更安静。
  · 老库自动升级：给名单加上 peer_id 列（老条目留空 = 暂时不参与告警），
      把「名字唯一」换成「PeerID 唯一」，删掉抓屏时代的 encounters 表。
      **名字与备注一个都不会丢**，升级前会自动整份备份（见下面「升级备份」）。

【怎么启动】

  HD2Blacklist.exe          ← 双击它就行，启动约 1 秒

  必须把**整个 HD2Blacklist\ 文件夹**一起带走（或整份解压出来），
  不能只拷 exe —— 旁边的 _internal\ 是运行库，少了它起不来。
  data\ 里是你的名单和配置，也在同一个文件夹里。


【前提：游戏里得装插件（这一步不能少）】
  本工具**不注入游戏、不读游戏内存**，它所有数据都来自一个日志文件：

    %LOCALAPPDATA%\CowboyBingus\Helldivers2\Logs\playerLog.txt

  这个文件是游戏内插件 HD2Tracker 写的。所以要装两样东西：
    1) 加载器 Bingus Shared Loader（HD2 的 addon 加载器）
    2) 插件 HD2Tracker —— 它是一个**独立的开源项目**，在这里：
         https://github.com/NealDai06/HD2Tracker
       下载、安装、配置、回滚都看它仓库里的 README。

  **两个必须一起用，缺一个都不工作**：插件在游戏里跑，负责把「这一局队里有谁」
  写成上面那个日志文件；本工具负责读这个文件、比对本地名单，
  名单里的玩家进队时提醒你。

  装好后**进一次游戏**，上面的 playerLog.txt 就会出现。

  【插件出处 / 致谢】
    这个插件的**本体框架是从下面这个开源项目扩张来的**：
      https://github.com/360de250/Helldivers2-SteamID-Tracker  （mod 名 kick，MIT 许可）
    并且在设计上**受下面这个项目启发**，还借用了它标定的 game.dll 布局做自校验：
      https://github.com/CowboyBingus/BetterLobbyManagement    （0BSD 许可）
    两位作者都写在程序的 THIRD_PARTY.md 里（连同两份上游许可正文）。

  怎么确认装好了：
    · 打开本工具的「最近遇到」页，「追踪状态」那一段会告诉你
      日志目录在不在、文件有没有、插件版本够不够新
    · 还没进过游戏时它会写「日志文件还没出现（插件没加载，
      或者还没进过任何一局）」—— 这是正常的，不是坏了
    · 想看插件到底加载成没成，看同一个目录里的
      BingusSharedLoader.log（加载器日志）与 playerLog.log（插件自己的诊断日志）


【怎么用】
  界面是一整页，从上到下分五段（没有菜单栏，功能都在这页上）：
     ① 最上面一行：追踪状态 + [最近遇到] + [暂停追踪] + [退出]
     ② 第二行：添加 / 编辑 / 删除 / 搜索 / 排序 / 导入 / 导出
     ③ 中间：名单列表（五栏：名称 / PeerID / 曾用名 / 备注 / 添加时间）
     ④ 底部一条标签栏：[最近遇到][通知][数据][帮助]
        —— 默认是**收起**的，点标签或右边的 [展开设置] 就打开；
        标签栏上面那条分隔线可以上下拖，想多看名单就往上拖
        （设置区最多占 60% 高度，所以「最近遇到」的列表可能要往下滚一点
         才看得全；想一次看更多就把分隔线往上拖）
     ⑤ 最底下：「最近动态」三行（带时间戳，最新在最上）+ 状态提示 + 统计
        —— 游戏启停、进入一局、有人进队/离队、命中、哪里失败了，
        都在这儿留痕，不用再去翻 app.log

  1. 双击 HD2Blacklist.exe
  2. 打开「最近遇到」—— 应该能看到刚才和你同队的人
  3. 选中一个 → [加入名单] → 想写备注就写（PeerID 已经填好了）
  4. 也可以点 [添加] 手动录入：只填名称就行。注意**没有 PeerID 的条目不会提醒**，
     只能先记着，等他出现在「最近遇到」里再补上 ID；
     名字是 `？` `★` 这类纯符号也没问题
  5. 名单里**同一个 PeerID 只会有一条**：再点一次 [加入名单] 不会多出一条，
     只会把他那一条的名字更新成最新的（他改名了）

  右键名单里的老条目还有一个 **[补全 PeerID]**：
  从「最近遇到」里挑一个人给他补上 ID —— 补上之后这条才会告警，
  而且他以后改名也照样认得出，别人取同名也不会误报。


【什么时候会提醒】
  只有一种情况会提醒：有人**刚进队**（插件写出 join 事件）、不是你自己、
  并且命中黑名单。

    有人刚进队（join）**且 PeerID 命中**   → 会提醒
    有人刚进队，但只有**名字**对得上       → 不会！名字会重名、会改，
                                             拿它当身份会认错人（见下一条）
    队伍快照刷新（squad）           → 不会（那是"现在队里有谁"的状态，
                                      拿它报警会把进队就在队里的人反复报一遍）
    同一个人的信息补齐（update）    → 不会
    有人离队（leave）               → 不会（只在「最近动态」里留一行）
    你自己                          → 永远不会
    在忽略名单里的人                → 不会（也不进「最近遇到」）
    同一局里 30 秒内重复进出的同一个人 → 只提醒第一次
    换了一局又遇到                  → 会重新提醒一次

  **提醒只认 PeerID。** 名单里没有 PeerID 的条目**不会提醒** —— 这是有意的：
  名字当身份既会认错人（别人取同名），也认不出改名。补 ID 有两条路：
  在「最近遇到」里重新 [加入名单]，或者右键那条 → [补全 PeerID]。
  从 v1 升上来的名单默认**全是**这种条目，启动时程序会在「最近动态」里
  直接告诉你还有几条。

  反过来说，有 PeerID 的条目**改了名字也照样认得出** —— 这正是拿它当身份的价值。
  而且局内一看到他名字变了，**名单里的名字会被自动改掉**（见下一条），
  你不用手动维护。

  一次进队多人命中：每人一个通知栏（垂直堆叠、互不遮挡），
  **音效只播一次**；超过 5 个时最后一栏是汇总（如「等 3 名：A、B、C」）。
  完整名单也会写进 data\logs\app.log。


【名单里的名字怎么自己变了？】（名字自动同步）
  这是故意的：局内只要看到某个 **有 PeerID 的条目**，他的名字和名单里写的不一样，
  程序就把名单里的名字改成**他现在的名字**。

  为什么这么设计：PeerID 才是身份，名字只是给人看的显示名。他改个名之后
  名单里还写着旧名字，过几天你自己都认不出这是谁 —— 不如当场跟着改。

  你能看到的痕迹（自动改你的数据，必须让你看得见）：
    · 状态栏闪一行「名单名字自动更新：旧名 → 新名」
    · 「最近动态」里留一行同名记录
    · data\logs\app.log 里写 `[改名] <PeerID>：旧名 → 新名`

  几条边界：
    · 只改**带 PeerID** 的条目（没有 ID 的条目连告警都不参与，自然也不改）
    · 名字为空（名册还没读到）时**绝不清空**名单里的名字
    · 同一个人的名字 5 秒内最多同步一次（挡名册抖动）
    · **备注不会被碰**；旧名字进的是「曾用名」栏（最多留最近 8 个）
    · 「曾用名」可以自己编辑（多个用 / 分开）或清空，它只给人看，
      不参与匹配、也不参与提醒
    · 改完之后弹出的提示里就是新名字（先改名、再提醒）


【明明遇到记录在案的人，却没提醒？按顺序排查】
  1. **名单里那条有没有 PeerID？** 没有就**不会提醒**（最常见的原因，
     尤其是刚从 v1 升上来的名单）→ 右键那条 → [补全 PeerID]，
     或在「最近遇到」里重新 [加入名单]
  2. 他是不是**刚进队**？如果你打开程序之前他就已经在队里了，
     那就只有「最近遇到」会记他、不会有提醒（提醒是事件驱动的）
  3. 他是不是在**忽略名单**里？「数据」页 → [忽略名单…] 看一看
  4. 是不是**同一局里 30 秒内已经提醒过一次**了？（去重窗口）
  5. 看「最近动态」那三行与 data\logs\app.log 里有没有 `[命中]` 这一行
  6. 还想更细地看：在 cmd 里跑
       python main.py --watch-debug
     它会实时打印日志里读到的每一行和解析结果（源码运行才有，打包版用不了）


【老条目不提醒了？】（v1 的名单升上来之后最常问的一件事）
  原因：v1 的名单里**只有名字、没有 PeerID**，而 v2 的提醒**只认 PeerID**。
  为什么不能退回按名字提醒：别人取个同名就会误报，而你真正想盯的人改个名字
  就漏了 —— 名字不能当身份。

  补 ID 的两条路（都在界面上点，不用手打）：
    · 「最近遇到」页里找到他 → [加入名单]（名字与 PeerID 都由程序填好）
    · 名单里右键那条 → [补全 PeerID] → 从「最近遇到」里挑一个人
  补完之后：
    · 这条开始正常告警
    · 他以后改名也认得出
    · 另一个人取同名也不会被误报

  顺带说一句：**同名不同人现在可以各留一条**（以前同名是加不进去的），
  「数据」页会显示「黑名单 N 条（可告警 M 条）」，M 小于 N 时就是还有条目没 ID。


【界面说「未找到插件日志」？】
  按顺序查这三件事：
    1. 加载器与插件装了没（见上面「前提」）
    2. 装好后**进过一次游戏没** —— 插件只在游戏里跑，不玩游戏它不写文件
    3. 看 %LOCALAPPDATA%\CowboyBingus\Helldivers2\Logs\ 这个目录里有没有
       BingusSharedLoader.log，里面 `load failed: <文件>:<行>: <错误>`
       就是插件加载失败的原因（最常见是插件版本和游戏版本对不上）
  另外：如果提示「插件版本过旧」，把插件更新到 **hd2trackerv21.2 或更新**即可 ——
  更老的版本字段不一样（没有 peer_id_hex / capture_id），界面会写清
  当前版本与要求的版本。


【暂停追踪是怎么回事】
  [暂停追踪] 只切换你自己的暂停开关，和"插件有没有在写日志"是两件事：
    · 暂停 = 停掉尾随线程。**暂停期间发生的事不会补报** ——
      这正是"别打扰我"的意思
    · 恢复 = 重新起线程，并且**从文件末尾重新对齐**（跳过暂停那一窗口）
    · 游戏没开时点它，指示灯不会变绿，只会显示「● 已暂停」


【「从列表移除」和「忽略此人」的区别】（很容易搞混）
    [从列表移除]  只是把这一条从「最近遇到」划掉。
                  下次再遇到他，照样会重新记录、照样会提醒。
    [忽略此人]    记进忽略名单。以后既不再提醒、也不再进列表。
                  后悔了到「数据」页 → [忽略名单…] → [取消忽略]。


【data 目录】（删掉会自动重建）
  notification.json   提示外观（文案 / 图片 / 颜色 / 字号 / 音效）
  assets\             应用图标 + 通知提示图；自定义图片 / 音效也会复制到这里
  blacklist.db        数据库：名单 + 「最近遇到」+ 忽略名单
  logs\app.log        运行日志（出问题先看这里）

  ⚠ 插件的日志**不在**这里，在 %LOCALAPPDATA%\CowboyBingus\Helldivers2\Logs\，
    那是插件的地盘，删了它下次进游戏会重新写出来。

  「数据」页里那两个按钮：
    [清空「最近遇到」]  清掉"遇到过谁"的记录（不动黑名单，也不动忽略名单）
    [忽略名单…]         查看 / 逐条取消忽略 / 整体清空

  列宽：名单和「最近遇到」的每一列都可以自己拖着改宽窄。
    最后一列的右边缘也拖得动 —— 它右边专门留了一小条空白用来让位。
    拖乱了想恢复默认：名单里右键 → [列宽自适应]；「最近遇到」页上也有同名按钮。


【导入名单的规矩】（导入**不会**清空你现在的名单）
  身份键：**有 PeerID 就用 PeerID，没有才退回名字**（大小写不敏感）。
  于是有两种"看着像冲突、其实不是"的情况：

    文件名同、PeerID 不同      → 是两个人 → **两条都留着**
    文件里 PeerID 相同、名字不同 → 是同一个人改了名 → **更新名单里的名字**
                                  （不论选哪种策略都会更新名字，因为"谁"是确定的）
    两边都没有 PeerID、名字相同 → 按名字当成同一个人 → 按策略处理
    文件里没 PeerID、名单里那条有 → 身份不同 → **各留一条**（有 ID 的那条不会被顶掉）

  只有 **同一个身份** 撞上时，才轮到策略决定备注与添加时间：
    · 跳过已存在的条目（默认）  什么都不改
    · 只更新备注                用文件里的备注覆盖，添加时间保持本机
    · 完全覆盖                  备注与添加时间都用文件里的值

  完成后提示「新增 N，更新 K，跳过 J（PeerID 命中后改名 M）」。
  导入是**整批一个事务**：中途任何一条出错就全部回滚，不会留下半份数据。
  导入功能**只读**你选的那个文件，不会改写它；也不会删表、清表。


【升级备份】
  从 v1 升级上来时，程序首次打开数据库会自动做三件事：
    · 给名单补上 peer_id 列（老条目留空 → 暂时不会提醒，补 ID 见上面）
    · 把「名字唯一」换成「PeerID 唯一」（同名不同人可以各留一条）
    · 删掉抓屏时代的 encounters 表（那套"命中流水账 + 证据截图"已经不用了）
  这次升级**不会丢名字与备注**（v1.0.x → v1.1.x 那次才会清空命中历史），
  但不放心的话先自己复制一份 data\blacklist.db 存着就行。

  更早的（v1.0.x → v1.1.x）结构备份还在，想找旧命中记录用：
    cd source_code
    python tools\legacy_schema.py --list       列出备份
    python tools\legacy_schema.py --backup     重新扫一遍并备份旧库
  ⚠ 这个工具是 v1.0.x/v1.1.x 时代的，只在你要翻老记录时用；
    v2 的库不要拿它来回转。

  ⚠ 证据截图（旧版 data\evidence\ 里的那些 jpg）在 v2 里已经没有任何地方
    引用了 —— 想留着当史料就留着，想清爽就删掉。


【拷给别人 / 换电脑】
  可以。这个包自带 Python 运行时与全部第三方库，对方**不需要装 Python**。
  但有几条必须注意：
    1. 必须拷**整个 HD2Blacklist 文件夹**，不能只拷 exe —— 旁边那个
       _internal\ 是运行库，少了它 exe 起不来
    2. 放在**可写目录**里（桌面、D:\ 都行）。别放 C:\Program Files：
       data\ 要写在 exe 旁边，系统盘受保护目录会失败
    3. 系统要求：Windows 10 / 11 **64 位**（在 Win11 x64 上打的包）
    4. 对方也得装**加载器 + 插件**，否则程序会一直说「未找到插件日志」
    5. 首次运行若弹出「Windows 已保护你的电脑」（SmartScreen），
       点「更多信息」→「仍要运行」即可（exe 没有数字签名）
    6. 你的黑名单、「最近遇到」、忽略名单、通知配置都在 data\ 里 ——
       不想一起给别人的话，删掉 data\ 再拷（下次运行会自动重建）
    7. 传之前建议压缩：整个文件夹压完通常小很多
    8. 想看自检结果（exe 没有控制台窗口）：
         cmd 里执行  start /wait HD2Blacklist.exe --check
       跑完后打开 data\logs\app.log，最后一段就是逐项 OK/FAIL


【想自己重新编译？】
  源码（含全部文档）就在 GitHub 仓库里：https://github.com/NealDai06/HD2Blacklist
  在仓库根目录（本地开发时就是 source_code\ 文件夹）执行：
    pip install -r requirements.txt
    python main.py --check              环境自检（先跑这个）
    python main.py                      直接跑源码
    python main.py --watch-debug        实时打印插件日志的每一行与解析结果
    python main.py --replay 日志文件     离线回放一份日志（不写库、不弹提示）
    python -m unittest discover -s tests -t tests   全量测试
    python build.py --clean             打文件夹版（产物到 ..\发布包\）
    python build.py --clean --onefile   打单文件版
  --clean 只清理本次要产出的那一份，不会动发布包里的其它东西；
  打包时会自动把本文件和 LICENSE 复制到产物旁边，所以不用手工维护两份。


【注意】
  · 本工具不注入游戏进程、不读游戏内存、不改游戏包、不抢焦点
    只读游戏内插件写在本机的一个文本文件
  · 但第三方自动化（包括游戏内插件本身）仍可能违反游戏 ToS，请自行评估风险
  · 提示窗口是 WS_EX_NOACTIVATE | WS_EX_TRANSPARENT，鼠标点击会穿透
  · 程序同一时间只能开一个：重复双击不会多开，而是把已经在运行的那个
    窗口从托盘/后台叫到前台（万一找不到窗口会提示「程序已在运行」）。
    要彻底结束请点主界面最上面那行的 [退出]，或托盘菜单「退出」，
    也可以在任务管理器里结束 HD2Blacklist
