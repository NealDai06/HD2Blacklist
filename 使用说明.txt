HD2 黑名单 v1.1.3 —— 使用说明
================================================================

【这一版（v1.1.3）改了什么】
  · 修掉"扫描功能失效"的真因：
      从源码直接跑 `python main.py` 时，如果没设 PYTHONPATH，程序就找不到
      仓库里自带的那些库（少了 rapidocr 就等于**没有 OCR**）。而 OCR 不可用时
      程序只会安静地返回"没识别到文字"，于是每一轮扫描都是"识别 0 个名字"，
      界面上看起来就是扫描坏了。
      现在：启动时自动带上这些库（不用再设 PYTHONPATH）；万一真的缺 OCR，
      启动后「最近动态」和状态栏会**立刻写明原因**，不会再让你猜。
  · 顺手让这类故障再也藏不住：
      - 点 [扫描聊天框] / 按 F8：OCR 不可用时直接告诉你"OCR 引擎不可用，
        扫描不会有结果"，而不是含糊地说"聊天框为空"（连抓屏都省了）
      - 按 ESC 触发菜单扫描：OCR 不可用时开局就收工，不再空转 8 秒
      - `python main.py --check` 的「OCR 引擎」一项会打印具体原因
  · 图标 / 名单 / 扫描逻辑都没有改动。

【上一版（v1.1.2）改了什么】
  · 名单变简单了，只剩三栏：**名称 / 备注 / 添加时间**
      删掉了「玩家ID」「TK次数」「遇到次数」「最后遇见」四个字段
      （数据库里的字段也一起删了，历史统计一并清空）
  · 为什么删：
      - 「玩家ID」根本不参与匹配，却出过一次真实事故 —— 名字填进了 ID 栏、
        名称栏留空，结果怎么都不命中（你上次遇到的就是这个）。少一栏，
        就少一类这种错。
      - 「TK次数 / 遇到次数 / 最后遇见」是每人一份的统计，平时没人看，
        还要在每次命中时做一次加一。现在名单只回答一个问题：
        **这个名字要不要提醒**。
  · 命中记录没有丢：每次命中仍然会写一条记录到数据库的 encounters 表，
    证据截图照旧落在 data\evidence\，底部「本局命中 / 今日命中」照旧统计。
  · 排序只剩「按添加时间 / 按名称」；右键菜单只剩 编辑 / 删除。
  · **老名单会自动升级，名字不会丢**：名称栏为空的老条目会用「玩家ID」
    补成名字（`PlayerX`、`？` 这种），彻底没名字的占位行才丢弃，
    并会在 data\logs\app.log 里写清楚保留了几条、丢了几条。
  · 导入导出只剩 名称 / 备注 / 添加时间 三列；老文件里多出来的字段
    一律无视，直接导入不会报错。

【上一版（v1.1.1）改了什么】
  · 修掉一个"明明在名单里却不提示"的漏检：
      添加玩家时如果**只填了玩家ID那一栏**、名字留空，而填的又是 `？` `★`
      这类纯符号名字，旧版本会在建索引时把它悄悄丢掉 —— 表现就是
      "聊天里明明出现了 ？，工具一点反应都没有"（v1.1.2 起这栏已经取消）
  · 底部能看见动态了：状态栏上方多了「最近动态」三行（带时间戳），
      按 F8 / 点 [扫描聊天框] 触发的每一次扫描、命中、被去重跳过、失败，
      以及游戏启动退出、菜单扫描结束，都会留在上面，按颜色区分：
      命中=绿、去重跳过=金、失败=红
  · 修掉自定义快捷键栏"说谎"：以前它会按**开机那一刻**的热键开关状态显示成
      「F8（未启用）」，之后你在顶部把热键打开它也不刷新。现在顶部开关一有
      变化就同步，并且会提示"总开关在主界面顶部"
  · 打包：本分发包**不含任何使用记录**（名单 / 证据截图 / 自定义图片音效 /
    配置都是空的，第一次运行会自己生成），可以放心直接发出去

【上一版（v1.1.0）改了什么】
  · 界面重排：菜单栏删掉，所有功能在一页上分五段；设置区默认收起、
    分隔条可以上下拖（详见下面「怎么用」）
  · 修掉两个"点了没反应"的开关：
      - 热键开关：以前按钮文字是「热键扫描：关」那种状态描述，而且在深色
        面板上没边框，看着就是一段灰字；点了也不会打开。现在按钮写动作
        ——[启用 F8 扫描]，点一下就开，开了变金色 [停用 F8 扫描]
      - 暂停监控：以前按了不生效，只会在日志里一遍遍刷「监控已恢复」
  · 监控指示灯现在说真话：游戏没开时点暂停不会显示成「监控中」

【怎么启动】

  HD2Blacklist.exe          ← 双击它就行，启动约 1 秒

  必须把**整个 HD2Blacklist\ 文件夹**一起带走（或整份解压出来），
  不能只拷 exe —— 旁边的 _internal\ 是运行库，少了它起不来。
  data\ 里是你的名单和配置，也在同一个文件夹里。


【掉帧怎么办】（触发扫描时游戏最低帧被拉低）
  已经默认做了这三件事，正常情况下不会干扰游戏：
   · 本程序整进程降到「低于正常」优先级、抓屏/OCR 线程降到最低，
     游戏永远优先拿到 CPU（抓屏+OCR 单次实测要 1~6 CPU 秒）
   · 菜单会话抓屏间隔 0.5 秒；画面连续静止 6 帧就自动收工
     —— 每次抓屏都可能让游戏卡一帧，所以「少抓」比「快算」更重要
   · 画面没变化就跳过 OCR（同一张图反复识别纯属浪费）
  想再省 / 想对比效果，改源码里的 app\config.py（见文末「自己重新编译」）：
   · GAME_FRIENDLY_PRIORITY = False   关掉优先级压制，看差别
   · OCR_UPSCALE = 1                  识别像素少 4 倍（小字号可能认不准）
   · ESC_SESSION["interval"] = 0.8    抓屏更稀


【怎么用】
  界面是一整页，从上到下分五段（没有菜单栏了，功能都在这页上）：
     ① 最上面一行：监控状态 + [启用 F8 扫描] + [扫描聊天框] +
        [暂停监控] + [退出]
     ② 第二行：添加 / 编辑 / 删除 / 搜索 / 排序 / 导入 / 导出
     ③ 中间：名单列表（三栏：名称 / 备注 / 添加时间）
     ④ 底部一条标签栏：[扫描与触发][通知][监视区域][数据][帮助]
        —— 默认是**收起**的，点标签或右边的 [展开设置] 就打开；
        标签栏上面那条分隔线可以上下拖，想多看名单就往上拖
     ⑤ 最底下：「最近动态」三行（带时间戳，最新在最上）+ 状态提示 + 统计
        —— 按了 F8、命中了谁、被去重跳过、哪里失败了，都在这儿留痕，
        不用再去翻 app.log

  1. 双击 HD2Blacklist.exe
  2. 游戏里把显示模式设成「无边框窗口」（全屏独占下截图会是黑的）
  3. 点底部 [监视区域] → [框选新区域]，依次框选三个监视区域
     —— 框小了等于永远识别不到东西，程序启动时会在日志里告警
  4. 点 [添加] 录入你要记录的黑名单玩家
     —— **只填名称**就行（就是游戏里显示的那个名字），备注随便写；
        名字是 `？` `★` 这类纯符号也能正常识别；同名只能有一条
  5. 想扫聊天框时点上面 [扫描聊天框]，或按你自己设的快捷键
     —— 老名单第一次用这一版打开时会自动升级，名字不会丢


【旧的数据结构已经留了底】
  这一版把数据库表简化了（删掉玩家ID与三个统计字段），老库第一次打开时会
  自动升级、并清空历史命中记录。升级前的旧结构和旧数据都留了底：

    _packaged_data_backup\legacy_schema_backup\
        README.txt             说明 + 恢复方法（先看这个）
        schema_old.sql         旧结构的建表语句
        empty_old_schema.db    旧结构空库（改名成 blacklist.db 就回到旧结构）
        db\*.db                6 份真实旧库副本（含你测试版那份 2 条名单 + 5 条命中）
        old_source\database.py 旧结构时代的实现（从 git 导出）

  想看/想恢复：

    cd source_code
    python tools\legacy_schema.py --list         列出备份
    python tools\legacy_schema.py --backup       重新扫一遍并备份旧库
    python tools\legacy_schema.py --restore extracted_data ^
           --to "..\发布包\HD2Blacklist\data"     恢复某一份（会先保底改名）

  提醒：升级会清空命中历史，所以 db\ 里那些副本是**唯一**还留着旧命中的地方，
  别删。原库（source_code\data、发布包\...）一个字节都没动。


【扫描没反应 / 什么都识别不到？】
  先看最下面「最近动态」那三行，按顺序排查：
   1. 有没有写着「OCR 引擎不可用，扫描不会有任何结果：缺少 rapidocr…」？
      → 这是程序缺了识别文字的库。用打包版 exe 启动，或用
        `python main.py` 启动源码（它会自动带上仓库自带的库）
   2. 状态栏说「聊天框为空」→ OCR 是好的，但聊天框区域里没框到文字：
      设置区 [监视区域] 里重新框选聊天框（只框文字本身，别框进大片背景）
   3. 说「上一次扫描还没结束」→ OCR 通常要 0.3~0.5 秒，等它跑完再点
   4. 说「命中 X，但 30 秒内刚提示过 → 本次跳过」→ 这是去重，不是没检测到；
      想立刻重新计就在 [扫描与触发] 里点 [清空命中去重缓存]
  另外 `python main.py --check` 会把「OCR 引擎」这一项的检查结果和原因
  都打印出来，直接跑一次最快。


【F8 没反应？先看最上面那个按钮】
  ① 上的按钮写的是「动作」：
    · 写着 [启用 F8 扫描] → 热键没开，**点它一下就打开了**
      （打开后按钮会变成金色的 [停用 F8 扫描]，再点就是关掉）
    · 已经是金色 [停用 F8 扫描] 但还是没反应 → 看状态栏提示，可能是这个键
      被别的程序（录屏 / 外设驱动）占用了，会自动退回「只有本程序在前台时
      有效」的轮询模式；到 [扫描与触发] 里换一个键即可


【按了 F8 之后到底怎么了？看最下面那几行】
  每一次触发都会在「最近动态」里留下带时间戳的一条，例如：
    15:03:16  按 F8：聊天框扫描完成，命中 1 条：PlayerX（已提示 + 已记录，786ms）
    15:03:31  按 F8：聊天框扫描完成，命中 1 条：PlayerX（30 秒内已提示过 →
              本次跳过，未重复计数，795ms）
  颜色也有用：命中是绿色、被去重跳过是金色、失败是红色。
  如果只看到「开始扫描聊天框…」而没有下文，说明这一轮还在跑或出了异常，
  下一次提示会补上结果；失败的原因（截图失败 / OCR 异常）也会写在这里。


【暂停监控是怎么回事】
  [暂停监控] 只切换你自己的暂停开关，和"游戏有没有开"是两件事：
    · 游戏没开时点它，指示灯**不会**变绿 —— 只会显示
      「● 已暂停 (手动暂停；游戏未运行)」
    · 游戏真的在跑时才显示「● 监控中」；日志里也只有在游戏在跑时才会写
      「监控已恢复」，否则写的是「已取消用户暂停（当前游戏未运行，不会扫描）」


【本轮修复】（按实机反馈）
  0) 界面重排：菜单栏删掉，重要开关提到最上面
     · 以前「启用 F8 热键扫描」「暂停监控」埋在 设置 菜单里，
       而且和工具栏的按钮重复（同一个设置两处都能改，还可能不一致）。
       现在每个功能只有一个入口：运行控制在最上面一行，名单操作在第二行，
       低频设置全在底部标签栏里。
     · 顺手修了个老毛病：按钮以前个个一样宽（不管写「退出」还是
       「扫描聊天框」），所以工具栏被挤成三行。现在按钮宽度跟随文字，
       两行就装得下，名单区比以前高了一截。
     · 又修了两个开关按钮"点了没反应"的毛病（实机反馈）：
       ① 热键按钮以前文字是"热键扫描：关"那种状态描述，而且在深色面板上
          没有边框，看着就是一段灰字 —— 你会以为"根本没有启动按钮"。
          现在按钮文字直接写动作：未启用显示 [启用 F8 扫描]，点一下就打开，
          打开后变成金色的 [停用 F8 扫描]。
       ② 暂停按钮和热键按钮以前都是"读当前值再写回去"，而不是取反 ——
          所以按了没反应，日志还一遍遍刷「监控已恢复」。现在都能正常切换了，
          而且只有游戏真的在跑时日志才写「监控已恢复」。
     · 工具带上的按钮现在都有可见边框（以前和背景同色，看不出能点）。
  1) ESC 菜单经常「什么都没检出」
     原因：判断「菜单是否打开」用的灰度标准差阈值（20）正好压在真实菜单
     截图的数值中间（实测 9.6~23.3），于是菜单明明开着也有一半概率被判成
     「菜单没开」，程序连扫描都不启动。
     现在改成看**平均亮度**（暗色面板 = 菜单开着），判不准时还会复查 3 次，
     最后宁可按「已打开」处理。升级即生效，不需要改任何配置。
  2) 玩家名就是一个问号 `？` / `?` 时不响应
     原因：这类「全符号名字」在两条路上都被丢掉了 ——
        · 归一化会把它变成空串，索引时被直接跳过（永远匹配不上）
        · OCR 判读又认为它「不含字母数字」，不像玩家名而丢弃
     现在：黑名单里存 `?` 或 `？` 都行（全角半角等价），走独立的「符号层」，
     只按整体相等匹配（所以聊天里打 "???" 不会误报）。
  3) 一次命中多个黑名单玩家，却只播报一个人
     原因：所有通知栏共用**一个**分层窗口，而 UpdateLayeredWindow 会重绘
     整个窗口并移动它 —— 后画的把先画的整个盖掉，只看得见最后一条。
     现在每个通知栏一个独立窗口，N 个玩家并排显示 N 栏；音效仍然只响一次；
     超过 5 个时最后一栏是汇总（例如「等 3 名：A、B、C」）。
     完整名单也会写进 data\logs\app.log。
  4) OCR 认错个别字符（0/O、1/l/I、5/S、8/B 等）导致漏检 → 增加「易混字符容错」
  5) 菜单里的「185级|功勋英雄」「小队」这类文字不再被当成玩家名
  6) 自定义提示图 / 音效更好用了（本轮新增）
     · 点 [浏览…] 时对话框默认就停在 data\assets
     · 选中的图片 / 音频会自动**复制一份**进 data\assets，配置文件里记的是
       这份副本 —— 原文件以后移动、删除、U 盘拔掉都不影响提示；
       同名同内容不会重复存，同名不同内容存成 xxx (2).png，不覆盖旧的
     · 音效格式从「只有 WAV」放宽到 WAV / MP3 / OGG / FLAC
     · [试听] 时路径为空或文件已删掉会直接提示，不再「点了没反应」


【识别不到玩家名？按顺序排查】
  1. cmd 里执行  start /wait HD2Blacklist.exe --check
     然后看 data\logs\app.log 最后一段，逐项 OK/FAIL：
       · 「监视区域尺寸」FAIL → 区域框得太小，重新校准
       · 「全符号玩家名」FAIL → 请反馈（正常应显示 OK）
       · 「自定义资源目录」FAIL → data\ 目录不可写，别把程序放在
         C:\Program Files 这类受保护目录，换到桌面或 D:\ 下
       · 「OCR 引擎」FAIL → 杀毒软件删了模型文件，重新解压
  2. 在 [校准区域] 里重框，**只框文字本身**，别框进大片背景
  3. ESC 菜单：按 ESC 后等菜单完全展开再等 1~2 秒；
     滚动列表时会一边滚一边扫，停下约 3.5 秒后自动收工
  4. 名字太长或含大量装饰符号时，OCR 可能只认出其中一段 ——
     建议在「名称」里录入完整的游戏内显示名


【扫描快捷键（可自定义）】
  底部 [扫描与触发] 分页 - 点那个按键框，直接按你想用的组合键
    · 点一下按键框，直接按你想用的组合键（如 Ctrl+F9、Shift+S）
    · 只按 Ctrl/Alt/Shift 会切换对应复选框，不会被当成主键
    · ESC 已被「菜单扫描」占用，不能绑定
    · 保存后立即生效，配置存在 data\hotkey.json
    · 默认是 F8，但默认未启用 —— 开/关在最上面那行的
      [启用/停用 F8 扫描] 按钮上（避免和游戏内按键冲突）
    · 热键注册为「系统全局热键」，游戏里（前台全屏）也能触发；
      启用后状态栏会写明是「系统全局热键」还是「按键轮询模式」
    · 若该键被别的程序占用，会自动退回轮询模式（只有本程序窗口
      在前台时才有效），换个键即可恢复全局生效


【排查：游戏里按 F8 没反应？】
  1. 看最上面那行的 [热键扫描：开/关]：写着「关」就点一下
  2. 看状态栏 / data\logs\app.log 里是「已注册为系统全局热键」
     还是「退回按键轮询模式：该按键已被其它程序占用」
     —— 后者说明 F8 被别的软件（录屏 / 外设驱动等）占了，换个键
  3. 在源码仓库根目录跑一次真机探测（会临时独占该键几秒后自动注销）：
       python tools\hotkey_probe.py


【data 目录】（删掉会自动重建）
  notification.json   提示外观（文案 / 图片 / 颜色 / 字号 / 音效）
  user_config.json    三个监视区域的坐标
  hotkey.json         扫描快捷键绑定
  assets\             应用图标 + 通知提示图；自定义图片 / 音效也会复制到这里
  blacklist.db        黑名单数据库（首次运行后生成）
  evidence\           命中时的证据截图（自动清理，默认留 500 张）
  logs\app.log        运行日志（出问题先看这里）


【拷给别人 / 换电脑】
  可以。这个包自带 Python 3.13 运行时、全部第三方库（numpy / onnxruntime /
  RapidOCR 中英文模型 / mss / pywin32 / pygame / tkinter）以及 VC++ 运行库
  （vcruntime140 / vcruntime140_1 / msvcp140），对方**不需要装 Python**。
  但有几条必须注意：
   1. 必须拷**整个 HD2Blacklist 文件夹**，不能只拷 exe —— 旁边那个
      _internal\ 是运行库，少了它 exe 起不来
   2. 放在**可写目录**里（桌面、D:\ 都行）。别放 C:\Program Files：
      data\ 要写在 exe 旁边，系统盘受保护目录会失败
   3. 系统要求：Windows 10 / 11 **64 位**（在 Win11 x64 上打的包）
   4. 第一次运行后必须**重新校准三个区域** —— 坐标是按分辨率/UI 缩放走的，
      换了电脑（或换了分辨率、全屏模式）一定要 设置 → 校准区域 重框
   5. 首次运行若弹出「Windows 已保护你的电脑」（SmartScreen），
      点「更多信息」→「仍要运行」即可（exe 没有数字签名）
   6. 你的黑名单、证据截图、通知配置、F8 设置都在 data\ 里 ——
      不想一起给别人的话，删掉 data\ 再拷（下次运行会自动重建）
   7. 传之前建议压缩：整个文件夹 ~290MB，压完通常小很多
   8. 想看自检结果（exe 没有控制台窗口）：
        cmd 里执行  start /wait HD2Blacklist.exe --check
      跑完后打开 data\logs\app.log，最后一段就是逐项 OK/FAIL


【想自己重新编译？】
  源码（含全部文档）就在 GitHub 仓库里：https://github.com/NealDai06/HD2Blacklist
  在仓库根目录（本地开发时就是 source_code\ 文件夹）执行：
    pip install -r requirements.txt
    python main.py --check              环境自检（先跑这个）
    python main.py                      直接跑源码
    python tools\hotkey_probe.py        真机验证扫描热键（全局热键探测）
    python tools\perf_probe.py          实测抓屏/OCR 的开销
    python build.py --clean             打文件夹版（产物到 ..\发布包\）
    python build.py --clean --onefile   打单文件版
  --clean 只清理本次要产出的那一份，不会动发布包里的其它东西；
  打包时会自动把本文件和 LICENSE 复制到产物旁边，所以不用手工维护两份。


【注意】
  · 本工具不注入游戏进程、不读内存、不改包、不抢焦点
    仅屏幕截图 + 本地 OCR + 本地黑名单比对
  · 但第三方自动化仍可能违反游戏 ToS，请自行评估风险
  · 提示窗口是 WS_EX_NOACTIVATE | WS_EX_TRANSPARENT，鼠标点击会穿透
  · 程序同一时间只能开一个：重复双击不会多开，而是把已经在运行的那个
    窗口从托盘/后台叫到前台（万一找不到窗口会提示「程序已在运行」）。
    要彻底结束请点主界面最上面那行的 [退出]，或托盘菜单「退出」，
    也可以在任务管理器里结束 HD2Blacklist
